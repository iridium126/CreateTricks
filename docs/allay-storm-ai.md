# Allay Storm Boss AI — 突袭分队设计文档

> 模组：CreateManaIndustry（机械动力：魔法工业）
> 版本基线：1.21.1 / NeoForge 21.1.227 / Java 21
> 前置阅读：`docs/allay-storm-sync.md`（风暴持久化与网络同步——本文全部架构约束的出处）
> 状态：**已实现（2026-08-30），compileJava/processResources 通过；GLSL 待进服实测**——落地记录：服务器波次状态机在 `AllayStormManager`（tickWaves/launchWave/handleWaveContact），走廊在 `AllayStormWaves`（高度图 A* + RDP + Chaikin×2 + 采样 ≤6 航点），共享哈希链 Java 移植与 GLSL 逐行对应（`cmiStormWaveRoll`/`cmiStormWaveGo`）；GPU 侧 `update.comp` 波次转向分支（pure-pursuit + whisker 锥 + 掠袭者跳过玩家排斥）、`wavecontact.comp` 接触自报检测（fence 回读 + 每成员每波去重）；竖井锚定 `CollisionBake.ensureColumn/ensureAnchorCell`（脚底对齐 + 16×16 滞回）。终局弧线（§10）仍未实现。
> 定稿方式：grilling 逐题评审（威胁模型 → 大脑权威 → 命中权威 → 选拔规则 → 俯冲形态 → 生命线 → 并发 → 节奏 → 生命周期 → 伤害 → 避障），每项结论均标注决策来源。

## 1. 定位与范围

Allay Storm 的 AI = **突袭分队**：成员定期脱离台风阵型，编队俯冲掠袭玩家，接触造成伤害，然后归队。除此之外风暴没有其他攻击手段。

**本轮不实现**（见 §10 终局弧线）：胜利条件、瘫痪武器、球形化、传送门、自定义维度决战。当前种群被杀光后风暴照旧空转（`/cmip allaystorm stop` 手动结束）——这是本轮的已知、已接受状态。

继承自同步文档的三条铁律，本文所有设计都不得违反：

1. **成员位置永不过网**——位置是各客户端 GPU 状态；位置相关的"智能"只能以事件 + 确定性派生的形式传达。
2. **事件驱动、零每 tick 常规流量**——AI 的一切同步都挂在低频事件包上。
3. **服务器所有必须一致的状态**——波次的发起、编队资格、伤害裁决全部服务器权威；客户端只在演出层自治。

## 2. 总览（一段话版本）

服务器大脑按**每玩家 60 s 冷却**（配置）发起突袭波次：目标必须**露天**（天空光检测）且距风暴中心 ≤96 格；编队规模 = 活跃种群 × 选拔比例（配置，绝对上限另设），成员资格由 `hash(memberIdx, waveSeed) < f` 决定性选出；服务器为每波算一条**走廊 A\* 折线**（波次级，非逐成员），随事件包下发；所有客户端 GPU 对同一事件做确定性响应——成员沿走廊掠袭目标、接触瞬间由**目标玩家自报**、服务器校验后以自定义 damage type 落伤害。≤4 波并发，GPU 波次 uniform 数组 4 槽。种群被磨掉 → 波次肉眼可见地变小变稀——**种群即血条**，血量从行为上可读。

## 3. 服务器大脑（`AllayStormManager` 扩展）

per-level Runtime 增加波次状态机，挂在现有 `tick()` 的 chase/grow 之后：

| 项 | 决策 |
|---|---|
| 触发 | 每玩家独立冷却 `stormWaveInterval`（默认 **60 s**）；冷却到点即检查资格，不合格顺延到下 tick（检查极廉价，见下） |
| 目标资格 | ① 玩家活跃（在 tracks 内）；② **露天**：服务器 `canSeeSky` / 天空光检测（在冷却到点时每玩家一次，非逐 tick——性能可忽略）；③ 距中心 ≤ `stormWaveRange`（默认 96，在淡出包络内） |
| 并发 | 最多 4 波同时活跃，各打不同玩家（每玩家同时最多 1 波） |
| 选拔 | `f = 活跃种群 × stormWaveFraction`（配置），绝对上限 `stormWaveMaxSize`；`waveSeed` 随机生成 |
| 走廊 | **波次级 A\***：服务器用方块数据从编队高度上方到目标上方算一条粗 voxel 走廊，**下发前做 2 轮 Chaikin 切角平滑**（voxel 折线必然带直角，切角后相邻段夹角受控），压缩为航点（几十字节）随包下发。每波一条、60 s 一条，成本可忽略。逐成员 A\* 不可行（CPU 无成员位置、GPU 优先队列串行、路径同步=位置过网），**否决记录在案** |
| 日程 | `{assembleAt, diveUntil}`，共享时钟秒域（与修正槽时间戳同域）；成员接触后或 `diveUntil` 到期即归队，无第三时刻 |
| 中止 | 仅目标失效（死亡 / 下线 / 切维度 / 离开激活范围）发中止事件；**编队被玩家杀光不中止**——死成员自然停止转向，幸存者飞完窗口归队 |
| 追逐高度 | `AllayStormData.CHASE_Y` → `ServerConfig`（实时读取；center 包已携带 Y，无新增线格式；成员经伺服缓动到新高度） |

## 4. 成员资格（GPU 侧，零新增 per-particle 状态）

成员在 shader 里保持无状态：每帧从活跃波次 uniform 数组（≤4 槽）推导自己的归属。

- 资格测试：`hash(memberIdx, waveSeed) < f`（复用 emit.comp 已有的身份哈希纪律——命名单乘语句、禁内联 `a*b+c`、宽幅进入哈希）。
- 多波去重：**按波次序先到先得**——依序测试各波，首个命中认领成员。服务器与所有客户端对同一规则达成零记账一致。
- 非俯冲期行为完全不变（`cmiTyphoonHome` 伺服）。

## 5. 俯冲行为（掠袭过场）

每个编队成员的时间表由波次日程驱动，三段式：

1. **集结**：从阵型 home 点飞向走廊入口（伺服目标切换，K=24 弹簧自然形成转向弧线）。
2. **掠袭（单次）**：沿走廊平滑航点（§3）接近目标玩家当前位置（客户端从本地玩家列表解析，与 chased center 同模式），每只成员**只尝试一次接近**——接近 → 接触 → 飞过，不反复飞掠。
3. **归队**：接触后（或 `diveUntil` 到期仍未接触）伺服目标切回 `cmiTyphoonHome`，软修正层吸收偏差。

**接触终结 = 不可逆锁存（2026-08-30 修复记录）**：首版把"单次"实现为纯位置推导（距目标 < 1.6 即视为已接触），但位置状态是**可逆的**——成员回转后 1-2 帧内重新越出接触半径，无状态哈希测试立即再次命中，成员在"追玩家/回家"之间以 ~2 Hz 翻转，被锁死在接触壳层上原地抖动直到窗口结束（实测确认）。修复：p0.w 身份打包的 **bit 18 为掠袭完成锁存位**（bits 0..17 = memberIdx+1，bit 17 被最大身份 131072 占用；打包值最大 393216，float 精确）——首个接触帧置位并随池压缩持久化，锁存成员永久跳过接战；全部 6 个身份提取点（memberMap/伤害匹配/修正槽/stormpos/wavecontact/capture）掩码 `MEMBER_IDX_MASK`。锁存同时根治了"被命中强修正拽回后二次接战"的衍生问题。已锁存成员仍可被近战命中（物理成员属性不变），stormpos 快照照常携带（归队途中仍受软修正）。

行为细节：

- **玩家排斥覆盖**：现有 update.comp 对 3 格内玩家的强排斥（权重 14）只对**非俯冲成员**生效，否则掠袭永远贴不上去。
- **走廊跟随（圆滑衔接，无直角折线）**：成员不逐段硬转——每帧伺服目标 = 走廊航点上**前方 lookahead 距离处的前视点**（pure pursuit），转向伺服（K=24 弹簧）把折线自动走成连续弧线；服务器端 Chaikin 切角又预先抹掉了大转角。高空水平段 → 竖井下降段的衔接：走廊末端航点取目标玩家上空、掠袭目标 = 玩家当前位置，两段在伺服里是同一目标函数的连续过渡，天然出弧线。
- **whisker 锥绕行（防卡死）**：现有碰撞只对**嵌入**（已在实体内）响应——成员从外面贴上玩家搭的顶/墙时每帧被清零轴向速度、被伺服压在障碍上悬停卡死（"轻易困住"的根源）。俯冲成员新增主动绕行：沿期望方向张一个 **~13 射线的探测锥**（直前、±35°、±70° 各若干，射程 2-3 格），被挡射线贡献排斥、自由射线按"偏离期望方向最少"择优，把转向目标弯到自由方向上——贴顶下不来时自动侧滑绕过檐口再继续下潜，被围墙挡时沿墙切向绕行。锥内全挡（玩家把自己封死）才落到现有逃逸扫描兜底。作用域：俯冲成员、有烘焙数据的区域（切片归属跟位置走）。
- **露天资格 ⇔ 走廊畅通**：天空光满格保证目标头顶垂直走廊无障碍——脚底 +32 格以上空域的主避障需求被资格规则从结构上消解。
- **俯冲窗口 = 反击窗口**：掠袭成员进入近战距离，现有 hit.comp / 近战管线**零改动**即可反打。杀掠袭者直接削减下一波选拔池。

## 6. 碰撞竖井烘焙

现状缺口（已实测确认）：烘焙象限只覆盖以**风暴中心**为准的 96×96 XZ 带（±48），俯冲目标最远 96 格且玩家位置每帧在变——**玩家附近（掠袭接触的发生地）完全没有碰撞数据**。

方案：**波次竖井**复用现有切片机制——

- `BAKE_SLICES = 8`：4 槽被 2×2 象限占用，剩余 **4 槽恰好给 ≤4 个并发波次各一条目标竖井**，零预留浪费、零新增机制。
- **`SY` 保持 32 不变**：每片构建固定 ~73k 次 `getCollisionShape` 后台查询，提 SY 直接翻倍烘焙 CPU 压力——否决。32 格预算全部花在玩家附近（见 §6.1），脚底以上空域由走廊 A\* 与露天资格承担。
- update.comp 的切片选择本来就是按位置归属（"第一个包含该位置的已烘焙体积胜出"），俯冲成员进入竖井自动获得碰撞，shader 零改动。
- 波次结束（到期/中止）释放竖井槽。

### 6.1 竖井的具体范围

**底层数据形态**：碰撞烘焙是**一张** `GL_TEXTURE_3D`（R8，NEAREST 过滤），沿深度轴堆叠 `MAX_SLICES = 8` 个独立切片，每片 `SX × SY × SZ` texel、**1 texel = 1 格**（255 = 有碰撞形状，0 = 空气）。每个切片锚定一个世界格点，覆盖 `[ax, ax+48) × [ay, ay+32) × [az, az+48)` 的方块体积。竖井就是其中一片，**下边界对齐玩家脚底、玩家居水平中心**：

| 维度 | 覆盖 | 锚定 |
|---|---|---|
| XZ | 以目标玩家所在方块为中心的 **48 × 48 格**柱面 | `ax = floor(px − 24)`、`az = floor(pz − 24)` |
| Y | **玩家脚底向上 32 格**：`[floor(feetY), floor(feetY) + 32)` | `ay = floor(feetY)` |

整数体素栅格下"水平居中"的精度：`floor(px − 24)` 把柱心放在玩家所在方块上，偏差 ≤ 1 格——已是栅格允许的最准。现有 `ensure(origin)` 以原点为中心锚定（`CENTER_Y = SY/2`），不合用，新增几行入口 `ensureColumn(px, feetY, pz)` → `ensureAnchor(floor(px−24), floor(feetY), floor(pz−24))`。

**设计取舍**：32 格预算全花在玩家附近——掠袭的接触发生在这里，玩家搭的顶/墙也在这里，**玩家附近的碰撞数据重要性远高于高空空域**（高空通常是空气，且走廊 A\* 已在服务器侧用完整方块数据绕开障碍）。脚底以上的 32 格覆盖：整个掠袭活动域（接触半径 ~1.5 格 + 绕行机动）、玩家头顶的反制建筑（2-3 格的顶、门洞、脚手架全部在内）。脚底以下的地面不覆盖——俯冲成员不落地，接触即归队。

**上段无覆盖（已接受）**：脚底 +32 格以上的整段下降没有碰撞数据，由三件事共同承担：① 露天资格的结构保证（天空光满格 ⇒ 头顶垂直走廊无障碍）；② 走廊 A\* 的航线本身——服务器有完整方块数据，航点只落在自由空间；③ 竖井内 whisker 锥绕行兜底（§5）。

**移动再锚定（滞回）**：玩家走动时竖井不能逐帧重锚——锚点格一变就是新槽位分配 + 后台重建。规则：玩家**走出柱心 16×16 内区**才重锚一次（滞回），波次活跃期间每帧重调 `ensureColumn`（自愈）；被替换的旧竖井切片仍是对那个位置**真实**的占用数据（体素是世界真相，不存在"过期即错误"），留到 LRU 自然逐出即可，反而是多出来的有效覆盖。

**职责边界**：竖井在**掠袭段**防两件事——掠袭期间被放置的方块（反制窗内搭顶/围墙）、贴着玩家切入柱内的山体/建筑边缘。**高空水平段**的绕障由走廊 A\* 负责：该段多在 ±48 象限带之外的烘焙盲区，GPU 本就无数据，靠服务器算出的平滑走廊路径本身避开障碍。

### 6.2 GPU 侧消费方式（俯冲成员怎么"撞"到竖井）

1. **切片归属（零改动）**：update.comp 每粒子先扫 `bakeMeta`（每片 `vec4{origin.xyz, presence}`），取**第一个包含该粒子位置的已激活体积**——归属跟位置走、不跟发射器走。俯冲成员一进入竖井柱，下一帧起自动按竖井切片做碰撞。
2. **点采样**：`solidAt()` = 相对坐标 floor + `texelFetch(uCollision, tc + slice*SZ)`，1 texel = 1 格、无过滤。一次探测 = 1 个 texel fetch。
3. **轴分离 substep 扫描**：每轴试探一步，受阻则清零该轴速度；MODEL 成员带 AABB 引导（水平 0.175、头部 0.6），帧位移 > 0.5 格自动细分 substep（俯冲 6 b/s × 最坏 0.25 s 帧 ≈ 1.5 格 → 4 substep）——隧道不可能。
4. **嵌入逃逸**：成员被困竖井内实体（中途搭方块）时走现有逃逸扫描（入口轴优先 → 六向最近 → 有界上升），竖井场景无新代码。
5. **激活延迟**：切片分配即时，但 `presence` 旗标在后台构建完成后才置位（后台守护线程 ~73k 次 `getCollisionShape` 查询、单构建在飞、每 20 tick 刷新已有切片）；波次集结段（秒级）天然覆盖这个延迟——俯冲开始时竖井已激活。
6. **零网络、天然跨端一致**：每个客户端从**自己的**区块同步数据烘焙，方块相同 ⇒ 体素相同，占用数据永不过网——与"成员位置永不过网"同一哲学。
7. **显存与 LRU 自愈**：纹理尺寸不变（48×32×384 ≈ 0.56 MB），零显存增量、`SY` 不动。8 槽全满时 LRU 逐出最旧切片——风暴路径已有自愈先例（`scheduleSpawnRuns` 每活跃帧重调 `ensureQuadrants`，杂散 burst 挤掉象限后下一帧补回）；竖井同款：波次活跃期间每帧重调 `ensureColumn`（重锚受 §6.1 滞回约束）。烘焙 CPU 压力与现状持平：每片仍 ~73k 查询、单构建在飞、每 20 tick 刷新。

## 7. 接触伤害（目标自报 + 服务器裁决）

**权威模型**：目标玩家客户端在视觉接触瞬间自报（GPU 每帧有精确位置，命中零量化延迟），服务器校验后裁决——与"死亡只由服务器裁决"同一哲学。

- 新包 `ServerboundStormWaveContactPacket`：`memberIdx` + `waveId` + 接触点（相对锚点 3×short ×16）。
- 服务器校验链：波次活跃 → **memberIdx 在该波编队中**（服务器用同一确定性选拔规则重算，零额外状态）→ 窗口内 → **每成员每波 1 次有效**（限速矩阵）→ 接触点距玩家服务器位置 ≤ 交互距离（plausibility，复用命中上报的 +8 余量哲学）。
- 伤害落地走 `player.hurt(source, amount)`：**vanilla 10 tick 无敌帧 / 护甲 / 吸收 / 不死图腾全部免费获得**，并发 DPS 天花板 = 单次伤害 × 2/s，与编队规模天然解耦。
- 击退：服务器从接触点 → 玩家方向计算（成员速度不上报）。
- 声音：攻击者本地预测（同现有命中音效预测模式），服务器 `playSound` 排除本人。

| 项 | 值 |
|---|---|
| damage type | 数据驱动 `createmanaindustry:storm_peck`（死亡讯息"X 被悦灵风暴撕碎了"系） |
| 默认伤害 | **7.0**（`stormWaveDamage` 配置，固定值不浮动）→ 无甲玩家约 1.5 s 持续接触致死，威胁成立且可脱身 |
| 饥饿消耗 | 0.1（vanilla 惯例） |
| 创造模式 | `hurt()` 自然免疫，零额外代码 |

**信任面记录（新增面 + 压制）**：自报接触是新的客户端可报告事件。收益分析：谎报只能给**自己**上伤害（无收益）；伪造他人接触不存在（包内无目标字段，ctx.player 即目标）；残余滥用 = 故意自报拉扯成员（强修正槽）→ 被"每成员每波 1 次"限速有界化。走廊、竖井、选拔、裁决全部服务器权威。

## 8. 网络协议（新增 2 个 payload，事件驱动）

| 包 | 方向 | 触发 | 内容（概量） |
|---|---|---|---|
| `ClientboundStormWavePacket` | S→C 广播 | 每波启动 / 中止 | `waveSeed` varint、`targetId` varint、`fraction` float、走廊平滑航点（Chaikin ×2 后，short×3 ×N）、日程 2×float（共享时钟秒域）、abort 标志位。~几十–百字节级 |
| `ServerboundStormWaveContactPacket` | C→S | 视觉接触瞬间 | ~13 B（同现有命中上报线格式风格） |

零每 tick 常规流量保持成立：波次 60 s 一发、中止罕见、接触每人每波 1 次。

## 10. 终局弧线（未来轮次，本轮仅记录）

**种群即血条 → 专属强力武器 → 瘫痪 → 决战**，用户愿景原文归纳：

1. 玩家获取**专属强力武器**（新增物品系统，未来轮）。
2. 武器可**瘫痪风暴**：风暴均匀聚集成**球形**（确定性的新 home-point 模式——技术上是被移除的 ball 模式的确定性回归，走波次 uniform 数组同款事件驱动，不走已退役的旧 wire 字段）。
3. 球形中心放置**通向自定义维度的传送门**。
4. 玩家进入自定义维度与风暴**决战**。
5. 胜利后**主世界风暴消散**（现有 STOP 广播路径 + 掉落/奖励，未来轮定义）。

设计占位：球形化 = 波次数组之外的一个全局模式槽；传送门/维度 = 独立系统，与粒子引擎唯一交点是风暴在维度间的可见性边界（现有客户端单风暴设计需在跨维度时明确 DEACTIVATE 语义）。本轮不写任何一行实现。
